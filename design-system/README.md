# Zixom Connect design system and prototype

Clickable HTML prototype of the Zixom Connect mobile app (Customer and Engineer roles). It is the design
reference for the React Native (Expo) build. Nothing here is app code: HTML, CSS, sample data and a little
vanilla JS to make the screens clickable.

Source of truth: `docs/Zixom Plast Mobile App Spec (Source of Truth) SCT-SP-APP-ZP Draft 2.pdf` (not committed).
Visual inspiration: `inspiration/` (not committed). Light mode only for now.

## Open it

Serve the folder, so fonts load in every browser:

```sh
cd design-system && python3 -m http.server 8000
```

Then open `http://localhost:8000/` for the screen map, or `/components.html` for every component.

## Structure

```
index.html              screen map: all 270 spec screens, links to the built ones
components.html         every component, rendered live, with the class to use
assets/css/zixom.css    the one stylesheet a page links (imports the rest)
  tokens.css            colours, type, radius, shadow, fonts
  plate.css             prototype chrome (frame, status bar, labels, state switch)
  base.css              screen shell, navigation, tab bar, buttons, chips, tags
  forms.css             fields, pickers, OTP, choice cards, switch, stepper, wizard, slots
  cards.css             cards, lists, machine and ticket cards, timeline, money, uploads, chat
  feedback.css          banners, toasts, alert, action sheet, bottom sheet, states, skeleton
  docs.css              layout of index and components pages only
assets/js/data.js       demo data from spec section 16, one source for every screen
assets/js/render.js     formats (dates, rupees) and HTML templates for data components
assets/js/ui.js         behaviour: status bar, tab bar, overlays, toasts, state switch
assets/js/screens.js    spec screen registry and the list of built pages
assets/icons/icons.js   Phosphor icon sprite, generated by tools/build-icons.mjs
assets/fonts/           Varela Round, Inter, JetBrains Mono (woff2, OFL)
assets/brand/           Zixom logo from zixom.in
screens/{access,system,customer,engineer}/<SpecID>-<name>.html
```

## Prototype chrome, never build this

Each screen page draws a phone so it can be judged on a laptop. These parts are scaffolding:

- The status bar (`.status`, 9:41, signal, battery). The OS draws it. In the app it is safe area padding.
- The home indicator (`.home-indicator`). Leave bottom safe area padding instead.
- The device frame (`.device`, 390 by 844, 44 px corners). Build fluid layouts.
- Everything outside the frame: `.plate-label`, `.plate-note`, `.plate-states`.

Build only what is inside `.screen`, including the tab bar and the overlays.

## Look

- Base: `inspiration/01-base-cafe-order.png`. Screens sit on a blue grey gradient; content is on a white
  sheet with 28 px top corners. Tab roots show a header on the gradient; pushed screens start the sheet
  under the status bar with round back and more buttons.
- Tab bar: `inspiration/03-car-marketplace-bottom-tab.png`. Floating; the current tab is a dark slate pill
  with icon and label, the others are white circles with a VoiceOver label.
- Colour: slate for primary buttons and text, brand blue `#4064D7` for links, selection and focus.
  Green, amber and red mean status only, and every status chip has text.
- Type: Varela Round (website font) for titles and buttons, Inter for body, JetBrains Mono for
  identifiers such as `TKT-2026-0123`.
- Logo: `globe.png` from zixom.in, used as is. It is 138 by 80 px on a white background, so place it on
  white only. Ask Zixom for the original (spec Q1).
- Images: machines and parts are a tinted block with a Phosphor line icon (spec section 3). People are
  initials.

## Conventions

- Icons: `<svg class="ic"><use href="#ph-wrench"/></svg>`. Need another icon: add its name to
  `tools/build-icons.mjs`, then run it against `@phosphor-icons/core@2` (instructions in the file).
- Data: read from `ZX.data`, render with `ZX.render` templates. Never hard code a ticket, machine or
  amount that exists in `data.js`.
- States: put `data-state="ready"` on `.screen`, mark content with `data-when="ready offline"` (any
  state names, space separated), and add buttons with `data-state` in `.plate-states`. A state button
  with `data-open="id"` also opens that overlay, for states that are a sheet or dialog.
- Overlays: an `.overlay` inside `.screen`, opened by `data-open="id"`, closed by `data-close`.
- Toast: `data-toast="Request saved as a draft"` on the trigger.
- New page: copy the skeleton below, then add its path to `ZX.built` in `assets/js/screens.js`.

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Zixom Connect - C101 Home</title>
<link rel="icon" href="../../assets/brand/zixom-logo-small.png">
<link rel="stylesheet" href="../../assets/css/zixom.css">
</head>
<body class="plate">
<div class="plate-label"><b>C101 Home</b><span>customer</span><span class="plate-tag">PHASE 1</span></div>
<div class="device">
  <div class="screen" data-state="ready">
    <div class="status"></div>
    ...
  </div>
</div>
<p class="plate-note">What this screen covers and which states the switch shows.</p>
<script src="../../assets/icons/icons.js"></script>
<script src="../../assets/js/data.js"></script>
<script src="../../assets/js/render.js"></script>
<script src="../../assets/js/ui.js"></script>
</body>
</html>
```

## Decisions on top of the spec (21 Nov 2026)

- Devices: 2 per customer, 1 per engineer.
- The minimum OS section is ignored.
- Notifications: push and email.
- Customer permissions are flat: everyone in a company sees and does everything (pay, approve estimates,
  add machines). Only the primary contact sees Team members and Change primary contact. No role field.
- Demo today is Monday 23 Nov 2026, IST.
