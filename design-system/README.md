# Zixom Connect design system and prototype

Clickable HTML prototype of the Zixom Connect mobile app (Customer and Engineer roles). It is the design
reference for the React Native (Expo) build. Nothing here is app code: HTML, CSS, sample data and a little
vanilla JS to make the screens clickable.

Source of truth: `docs/Zixom Plast Mobile App Spec (Source of Truth) SCT-SP-APP-ZP Draft 2.pdf` (not committed).
Visual inspiration: `inspiration/` (not committed). Light mode only for now.

## Open it

Serve the folder, so fonts load in every browser:

```sh
cd design-system && python3 -m http.server 8000
```

Then open `http://localhost:8000/` for the screen map, or `/components.html` for every component.

  motion.css            spring press, selection, overlay enter and exit, tab pill

## Prototype chrome, never build this

Each screen page draws a phone so it can be judged on a laptop. These parts are scaffolding:

- The status bar (`.status`: 9:41, Dynamic Island, signal, battery). The OS draws it; in the app it is
  safe area padding. ui.js picks its look: the page colour on pushed screens, white text over the gradient.
- The home indicator (`.home-indicator`). Leave bottom safe area padding instead.
- The device frame (`.device`, 390 by 844, 44 px corners). Build fluid layouts.
- Everything outside the frame: `.plate-label`, `.plate-states` and the `.plate-info` sticky notes (What it is,
  What you can do, What happens next, Edge cases and spec) that sit beside the phone and can be closed.

Build only what is inside `.screen`, including the tab bar and the overlays.

## Look

- Base: `inspiration/01-base-cafe-order.png`. Tab roots have a blue grey gradient header over a sheet with
  28 px top corners. The app background is a soft grey gradient (`--surface`), never pure white; cards and
  fields are white with a hairline border. Tab roots show a header on the gradient; pushed screens start the sheet
  under the status bar with round back and more buttons.
- Tab bar: `inspiration/03-car-marketplace-bottom-tab.png`. Floating; the current tab is a dark slate pill
  with icon and label, the others are white circles with a VoiceOver label.
- Colour: slate for primary buttons and text, brand blue `#4064D7` for links, selection and focus.
  Green, amber and red mean status only, and every status chip has text.
- Type: Varela Round (website font) for titles and buttons, Inter for body, JetBrains Mono for
  identifiers such as `TKT-2026-0123`.
- Logo: `globe.png` from zixom.in, used as is. It is 138 by 80 px on a white background, so place it on
  white only. Ask Zixom for the original (spec Q1).
- Images: machines and parts are a tinted block with a line icon (spec section 3). People are initials.
- Icons: Lucide, 1.75 stroke, round caps. Back buttons are a plain chevron.
- Copy: short and compact. One line under a title, no explanatory paragraphs, only what the person needs.
- No logo inside the app except the splash. Auth screens put the back chevron and title on one row.
- Motion: one spring curve (`--ease`) for things arriving, responding and leaving; leaving is faster.
  Buttons and cards press with a spring, selections settle on a spring (segment thumb, chips, switches),
  overlays and toasts animate in and out, and the tab pill glides to the tab you open. Page changes do
  not animate. Reduced motion turns all of it off.

## Conventions

- Icons: `<svg class="ic"><use href="#ph-wrench"/></svg>`. Names are ours and map to Lucide files in
  `tools/build-icons.mjs`; add a line there and rebuild against `lucide-static@0.460.0`.
- Data: read from `ZX.data`, render with `ZX.render` templates. Never hard code a ticket, machine or
  amount that exists in `data.js`.
- States: put `data-state="ready"` on `.screen`, mark content with `data-when="ready offline"` (any
  state names, space separated), and add buttons with `data-state` in `.plate-states`. A state button
  with `data-open="id"` also opens that overlay, for states that are a sheet or dialog.
- Overlays: an `.overlay` inside `.screen`, opened by `data-open="id"`, closed by `data-close`.
- Toast: `data-toast="Request saved as a draft"` on the trigger.
- Search: any `.search` filters the list under it (after 2 characters, 300 ms pause), shows a spinner then a clear
  button, and a Clear search state when nothing matches. `data-search-item` marks custom rows; `data-search="own"`
  opts out. A filter button always sits on the same row as a search input.
- Tab roots: wrap the header and sheet in `.root-scroll` so the header scrolls away with the content.
- Uploads: `.files > .file[data-status]`, statuses queued, uploading, paused, done, failed, too-large,
  wrong-type, duplicate, missing; buttons with `data-file="pause|resume|retry|remove"` work.
- Links between screens: use the names in `ZX.files` and run `node tools/check-links.mjs`.
- New page: copy the skeleton below, then add its path to `ZX.built` in `assets/js/screens.js`.

## Decisions on top of the spec (21 Nov 2026)

- Devices: 2 per customer, 1 per engineer.
- The minimum OS section is ignored.
- Notifications: push and email.
- Customer permissions are flat: everyone in a company sees and does everything (pay, approve estimates,
  raise service). Only the primary contact sees Team members and Change primary contact. No role field.
- Demo today is Monday 23 Nov 2026, IST.

## Decisions on top of the spec (26 Nov 2026)

- No customer sign up in the app. Zixom creates the company, its people and machines in the admin dashboard and
  sends app access by SMS. People sign in with mobile number and OTP only, no passwords.
- Removed: A05 to A09 (sign up and verification) and C203 Add machine. The screen map lists them as Removed.
- A number with no account reaches A26 No account for this number after the OTP: Call Zixom, WhatsApp, Try
  another number. A18 is now the first sign in from Zixom's SMS invite.
- Only Zixom adds people and machines. The primary contact can only Request a new user (C1105, sent screen
  C1117) and anyone can Report a missing machine (C204). Both go to Zixom's work queue and show as Requested
  until Zixom adds them, usually within 1 working day.
- C205 Scan QR stays: it finds one of your machines (Machines, AMC, raise service). An unknown QR offers Report
  a missing machine.
